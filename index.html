Build order

The order to build in. Each step needs the ones before it.

  1. ADR-000: System architecture, ADR-001: Multi-tenant database architecture
    The skeleton: modules and ports, the outbox, the egress gate, tenancy and row-level security. Every later record is a module on top.
  2. ADR-010: Users, roles and access, ADR-013: Sign-in
    Users, roles and sign-in are part of the skeleton: every later module names its actions, and ADR-010 decides who holds them. Sign-in, sessions and operator grants exist before any screen shows a buyer's address. Sign-in is its own Worker running Better Auth, with its own build, deploy and auth schema in control, so it is set up with the skeleton; Better Auth hands ADR-010 a login id and decides nothing about access.
  3. ADR-003: Product model
    Products come first; listings, stock and orders all point at them.
  4. ADR-006: Stock ledger and reservations
    Stock is recorded and reserved inside Vervoro before any marketplace sees a figure. Only Inventory writes it.
  5. ADR-004: Channel connectors, ADR-004.1: eBay connector, ADR-004.2: Amazon Seller connector, ADR-004.3: Shopify connector
    The connector host first, then eBay and Amazon Seller side by side. Shopify (ADR-004.3) is Later, built when a seller needs it. Each runs against its simulator in shadow mode. Amazon Vendor (ADR-004.4, planned) comes later.
  6. ADR-005: Catalogue sync and linking
    Needs the connectors' listing reads and the products to link them to.
  7. ADR-009: Buyer data and privacy
    Before any real order stores a buyer's address; the marketplaces' data reviews ask for it. Buyer anonymisation from ADR-002 is built here.
  8. ADR-007: Order ingestion, ADR-014: Fulfilment
    Orders need links, reservations and the buyer-data rules. Fulfilment then picks, packs and ships them, and takes returns, through Inventory's and Orders' ports.
  9. ADR-011: Invoicing and VAT
    Invoices follow orders: needs order lines, refunds, the buyer-data rules and the roles. Built before any real sale, so every sale line has its VAT record from the first day.
  10. ADR-012: Billing and plans
    Before any connection goes live: going live needs a payment method, the stop choice (leave the figures or send zero) and a stock contact, even in a trial. It is beside the stock path, never in it: nothing in it stops orders or stock.
  11. ADR-008: Inventory sync
    Last before launch: figures go to marketplaces only once links, the ledger, orders and the go-live checks are proven in shadow mode.
  12. ADR-002: Data retention and archiving
    The log drops run from launch; archiving is switched on by its trigger (a cell past 500 GB, or the start of year 2).
